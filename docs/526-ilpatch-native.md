# 526. IL patcher, native half: `[IlPatch]` applies the docs/506 specs at Mono's IL transform

Written 2026-11-02 (contributor round 8, B1 native half; the offline half is docs/521). Static + disassembly + the native
selftest; the live smoke is listed in §6 with its state. Nothing here ships on: `[IlPatch] Enabled=0` and every fix switch 0.

## Summary

`native/ts3native/ilpatch.cpp` (next version, counters v900 `ilp*`) detours the Mono IL transform entry `0xE643B0`. For a
method one of the armed specs names, it reads the IL body through the method's cached header, hashes it, and on an exact size
and SHA-256 match with a build the spec knows (EA 1.67 or simler90 UPDATE242, docs/506 §1) splices the spec's instructions into a
copy of the body: the relocator of `tools/ilpatch-convert.ts` ported (every branch re-encoded long, switch tables re-targeted,
exception clauses moved, max stack raised by the spec's figure). The copy's SHA-256 must be the converter's `patchedSha256`
for that build; then the header's size, code pointer, max stack and clause records point at the copy for that one transform
call and are put back after it, also when the transform faults. Any other body (another core mod, Tiny UI Fix, an unknown
build) is left alone and logged once. The specs are compiled into the asi as a C table (`ilpatch-specs.h`, generated by
`node tools/ilpatch-convert.ts --emit-native`: opcode kinds, names, hashes, tokens and our instructions; no EA bytes).

The three fixes of docs/506 §5 are in the table: `ilp_fixupnoinventory` (core build 89, `SimDescription.Fixup`),
`ilp_remotechatnoeverydayoutfit` (build 80, `Sims.DoOneRoundOfRemoteChat`), `ilp_scavengersleep` (build 87,
`ScavengerOpportunity.OnAdded`).

## 1. The transform and the header [verified: capstone listing of `TS3W.exe` 1.67 in `game-copy/bin`, 2026-11-02]

- `0xE643B0` is `void* __cdecl transform(RuntimeMethod* rm, void* ctx)`, prologue `55 8B EC 83 EC 78` (6 bytes, the detour's
  copy). `edi = rm+8` is the MonoMethod, `ebx = rm`. satb.cpp's cold site 0 (`kSatbCold[0]`, docs/206 §7) is the same entry:
  with both on, ilpatch owns the detour and calls `SatbColdEnter(0, rm)` first (`g_ilpColdEnter`); Satb installs nothing there.
- It calls `mono_method_get_header 0xE85390` (cdecl, MonoMethod*), which returns the header cached at `MonoMethod+0x20` and
  fills it under the loader lock `0x11F43A8` only on a miss. `GenerateCode 0xE5CA90` (MonoPatcher's site, docs/06) reads the
  same cached header one call later.
- Header layout: `+0` code size, `+4` code pointer, `+8` max stack (16-bit: `imul dx,dx,0xa` at `0xE6494C` scales it),
  `+0xC` bits 0-14 clause count (`test [edi+0xC],0x7fff` at `0xE5CBED`; bit 15 is a flag the swap keeps), `+0x10` locals
  count, `+0x14` clause array (24-byte records: flags, try offset, try length, handler offset, handler length, class token or
  filter offset; the loop at `0xE5CC06`-`0xE5CC7C` steps `0x18`), `+0x18` locals.

So the swap of `+0`, `+4`, `+8` and the clause records for the call is what I-506-1 asked for: the transform reads nothing
else of the body. The header stays cached, so a later transform of the same method (MonoPatcher's ForceJIT) sees EA's fields
again and gets the same swap (`ilpReused`).

## 2. Flow (`ilpatch.cpp`, 364 lines)

1. `ApplyIlPatch(ini)` at start-up, before `ApplyMintCall` and Satb: `[IlPatch] Enabled=1` and at least one fix switch, SHA-256
   through bcrypt, the 6-byte prologue intact, `InstallDetour` at `0xE643B0`. Log `OK   il patch (docs/506 §2, docs/526): N
   of M fixes armed; ...`, one `il patch: <id> armed ([IlPatch] <switch>=1): <method>, N known build(s), N edit(s)` per fix;
   `SKIP il patch: ...` when bcrypt or the prologue is not as expected (another mod or probe owns the entry: no fix applied).
2. `IlpXform(rm, ctx)`: the Satb client first, then `IlpMatch` (namespace, class and method name read as monohost's
   `JitMethodName` does: `rm+8 -> MonoMethod`, `+8 -> class`, class `+0x34` name / `+0x38` namespace, method `+0x18` name,
   under `__try`). No armed spec: straight through to EA's transform.
3. First time for a matched method: `IlpBuildPatched` hashes the body (`ilpSkipHash` when no build matches: logged once with
   the size and 8 hash bytes), runs `IlpApply` (refusals in §3: `ilpSkipCheck`), checks the result's SHA-256 against the
   converter's (`ilpSkipMismatch`: "relocator mismatch, report it"; the fix stays off for that method). The patched body, its
   clause copies (EA's and ours) and sizes are kept per spec.
4. `IlpTransformPatched`: swap, `__try { EA's transform } __finally { restore }`, `ilpApplied` on the first call,
   `ilpReused` after; one `il patch: <id> applied to <method> (<build>, N -> N bytes, max stack N -> N, N clauses, patched
   sha256 ... as the converter's)` line.
5. A fault anywhere in the patcher's own reads (`ilpFaults`): the fix is off for the session and the call goes to EA's
   transform untouched.

## 3. Relocator checks (the converter's rules, ported)

Refused, with the reason in the log: a body that does not decode; more than 64 clauses or 16 edits; an edit offset that is
not an instruction start; opcodes at an edit offset that are not the spec's `expect`; a branch target inside a replaced range
or not an instruction start; our branch into or out of the exception region of its edit (I-506-3: Mono does not check it, so
the patcher does); a branch to a line the edit has not got; a token index past the build's list; an operand kind the table
does not carry. Insertions move the clause boundaries after them and an insertion at a boundary keeps the original side
(`incoming`), as the converter.

## 4. Counters (v900, `docs/registry.md`; the probe's `nativeCounters` lists them from version 900 on)

| Field | Offset | Meaning |
|---|---|---|
| `ilpOn` | `0x5590` | the transform detour is installed |
| `ilpArmed` | `0x5594` | fixes with their switch on |
| `ilpApplied` | `0x5598` | methods transformed with a patched body (first time each) |
| `ilpReused` | `0x559C` | repeat transforms of a patched method that reused the body |
| `ilpSkipHash` | `0x55A0` | listed methods whose body is not a build the fix knows |
| `ilpSkipCheck` | `0x55A4` | bodies refused by the decoder or the relocator, or with no header |
| `ilpSkipMismatch` | `0x55A8` | patched bodies whose SHA-256 is not the converter's |
| `ilpFaults` | `0x55AC` | faults inside the patcher (fix off for the session) |

## 5. Tests

- `selftest.exe` (`ilpatch-test.h`, `TestIlPatch`): SHA-256 "abc"; the decoder on one- and two-byte opcodes, short and long
  branches, a switch, a truncated operand, a bad opcode, the row cap; the relocator cases of the converter's `--self-check`
  (a short branch over 130 inserted nops becomes long and the clause moves with it; an incoming insert at `ret` with a token,
  a branch back to an original offset and a branch to one of our lines; a replace; a switch case re-targeted; an insert at the
  end of the body) with the expected bytes; the refusals (branch into a replaced range, wrong `expect`, cross-region branch, an
  offset inside an operand); the header swap around a fake transform (the fake sees the patched size, code, max stack and
  clause, the header is back after the return and after a fault, `ilpApplied` moves, `ilpReused` does not on the fault); the
  whole detour on a runtime method named as spec 2 whose body no build matches (hash skip once, EA's transform runs) and on a
  method of another name (straight through).
- `node tools/ilpatch-convert.ts --self-check` (unchanged) and `--emit-native` regenerates `ilpatch-specs.h` byte for byte.
- Live: `tools/harness/queues/ilpatch-smoke.json` (Baseline-BP-Spring, the three switches on, 5 min of play): requires the
  `OK` line, `b89-fixup-no-inventory applied to ...SimDescription::Fixup() (ea-1.67, 1445 -> ` (every Sim's `Fixup` runs at
  the world load), three `armed` lines; forbids any refused / mismatch / fault / `left alone` line.
