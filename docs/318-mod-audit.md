# 318. Static audit of other modders' script mods (compat set, 2026-11-22)

Status: static only (no game runs). Every script mod in our compatibility download set (`game-copy/compat-mods`, 96 ModTheSims items on 2026-11-22 09:31 PHT) was read. Of these, 57 carry script code (S3SA assemblies) and were audited, and 39 are tuning or CC only and were skipped. Fixing these mods is not our job. Each issue gets a report to its author with a sample fix, pending Rodney's OK. Status of every report: **reported: not yet**.

## Method
- Unpack: `.zip` / `.rar` / `.7z` with Windows `tar` (libarchive), assemblies pulled from each `.package` by `tools/extract-assemblies.ts` (`s3saImages`). Per-patch or per-EP builds of one mod were deduplicated by hash.
- Read: each assembly decompiled with ilspycmd 11.1 (C# + full IL dump) against the vanilla Steam 1.67 script assemblies. The newest 1.67-compatible build of each mod was audited in full, and the other builds were diffed against it.
- Core mods that replace an EA assembly (2x Weight and Fitness, simler90 core, xCAS) were diffed against vanilla 1.67 with an order-insensitive per-file line diff. This drops compiler-name noise: for example, 780 textually different files came down to 9 with real changes for the 2x mod.
- Checklist per mod: listener and alarm lifetime, static collections, objects created and never destroyed, per-Sim caches, world-quit cleanup, unguarded nulls, exceptions in alarms, events and tasks, unbounded loops or waits, save contents and uninstall behaviour, per-tick scans, and overlap with our fixes (compat matrix, branch `feature/compat-matrix-1122`).
- Two lifetime facts were checked in EA code and used across all mods. EventTracker listeners are dropped at world shutdown, so re-adding them on every load is not a leak. The static `World` events in SimIFace (object placed in lot, etc.) are never cleared, so adding one per world load makes a small, growing handler list. The second review rated this minor: each call costs microseconds, and the handlers keep nothing from the old world alive.
- Full per-mod reports (code citations, sample fix diffs) and draft author messages are kept private and out of git. Decompiled code of other mods is never committed or quoted here.

## Second review (2026-11-22)
Every finding above minor (47) was re-checked by a second, adversarial pass that tried to disprove it, plus 10 minor ones as a spot check. The assemblies were decompiled again (ilspycmd 11.1, IL), and the EA 1.67 code each finding leans on was read. Every crash and hang verdict was checked by the lead reviewer in person.
- **Verdicts:** `confirmed` means the code and the path a player reaches were both seen. `possible` (plausible) means the code is as described, but whether play reaches it, or what EA does next, is not proven. `rejected` findings were removed from the table below.
- **12 first-pass findings were rejected on review:** 1 hang, 2 leak, 8 save, 1 minor. The main reasons:
  - Save findings (8): without the mod, EA's loader quietly drops saved mod moodlets, timers, object parts and situations whose type is missing (5). Two were normal leftovers that any custom object leaves behind. In one, no mod data reaches the save at all.
  - A Sim's inventory has no size limit (Treasure Box).
  - An empty "wait while routing" loop always ends at once, because the route call before it has already finished (Online Pharmacy).
  - The base game does the same in the same case (Cook With Any Ingredient).
  - The first pass misread a branch (Aussomedays Entry Slots).
- **Severity changes:** Drinks moved from hang to crash. It is a script error that stops the Sim's needs updating, not a wait. Handlers added again on each world load cost microseconds per call and hold nothing from the old world, so they moved from leak or perf to minor (Builder Stuff, More Alchemy Potions, Moar Interactions, Buy Takeout, Study Skills Online). Mod data that a mod deliberately keeps in the save, and that EA drops cleanly once the mod is removed, moved from save to minor. Statue of Life's double pregnancy timer is a gameplay bug, so it moved from leak to minor. Consort Grow's outfit builders are freed later by EA's finalizer, so that finding moved from leak to minor.
- **Versions:** the audited build is the newest script build in the download for all 27 mods with a draft (assembly hashes compared per archive). Two labels were corrected: Growing Pains (the package in the current download is newer than the listing date) and Aussomedays Entry Slots (two parallel builds, not old and new).

## Labels
- **Evidence:** `verified` means seen in the IL, with the method and IL offset cited in the private report. `inferred` means reasoning only, and the report says what would confirm it.
- **Severity:**
  - `crash`: a script exception that aborts a game code path, such as a world load or quit handler chain or a lot update. Usually this is not a crash to desktop.
  - `hang`: an unbounded wait or loop.
  - `leak`: memory, handlers or objects that are never released.
  - `save`: mod data or mod types in saves, or uninstall risk.
  - `perf`: extra work in a hot path.
  - `minor`: wrong behaviour without lasting harm.
- **player:** whether normal play can hit it (`yes` / `rare` / `no`).

## Totals
Audited 57, skipped 39.
- **First pass:** crash 4, hang 7, leak 11, save 19, perf 6, minor 52.
- **After the second review:** crash 5 (3 confirmed, 2 possible), hang 5 (2 confirmed, 3 possible), leak 4, save 2, perf 2, minor 69 (of these, 42 first-pass minor findings were not re-checked). 12 first-pass findings were rejected on review.
- **Mods with no findings:** 14 of the 57 audited mods have none (12 from the start, 2 more after review).
- **Author drafts:** 27 drafts were written, one for every mod that had a finding above minor in the first pass. 15 still have one after review. The other 12 are kept private and not sent.

Most relevant to players:
- **Builder Stuff (450059):** two of its parts throw an error on every world load and quit. Mods that hook in after them can then miss their own load or quit step. Confirmed.
- **Drinks for your Sims (399992):** in one rare case, when the drunk timer runs out, a script error stops that Sim's needs and moodlets from updating until the Sim is reset. Confirmed.
- **More Romantic Interactions v2 (691427):** a script error in a lot's background update when a couch proposal has an Inappropriate or Insane bystander. Confirmed.
- **MSC More Sims in Clubs (552227):** v3 reminders are saved and added again on every load, so they multiply. Confirmed.
- **Dexter the Bear (372599), Weapons System (402950):** the arresting officer waits forever if the suspect cannot reach the police car. Confirmed.
- **Consort Grow (490536):** every tracked child's outfits are rebuilt at once each sim-day at 1 AM. Confirmed, hitch size not measured.
- **Online Pharmacy (455990), Animation Player (441682), More Alchemy Potions (493140):** possible freezes or stuck Sims. The code waits without a limit, but the failure that would trigger it is not proven.

StoryProgression and our features (verified unless marked):
- **Our EA story-progression fixes go idle.** StoryProgression switches EA's own story progression off, so those fixes never run. Nothing breaks.
- **Visits and trips home** that StoryProgression sends go through our visit, routing and unseen-Sim fixes. It adds many more of these trips, but replaces none of the code.
- **Sim creation.** NRaas creates Sims with its own copy of EA's code, so our three Sim-creation fixes (outfit deferral, age-up duplicate, resident spawn slot) do not run for those Sims. This is ours to fix.
- **School trips** (StoryProgression Career, NRaas Careers) use their own copy of the rabbit-hole entry, so our speed-up there is lost. Nothing breaks.
- **Autonomy scoring work on other cores (AutShadow, go-live):** no overlap. StoryProgression pushes actions directly and does not score autonomy.
- **Household Sims:** StoryProgression gives household Sims work, school and money actions that the base game does not. Our household checks read household membership live, so household Sims never take an unseen-Sim path. A check that household play matches vanilla must run with StoryProgression off.

GoHere has the largest overlap of any mod read so far. Our unseen-Sim fallbacks deliberately stand down for NRaas interactions, and GoHere puts its own interaction on most NPC trips. Its community-lot visit never calls EA's code, and its routing skips one of our route-option fixes. So with GoHere installed, much of our unseen-Sim routing work does not run (inferred from the code; not measured).

In-game checks worth running: GoHere on and off on the same world (visit and unseen-routing counters), a townie created by StoryProgression seen after being off screen, a WooHooty text with Woohooer, and StoryProgression on and off on a big save (hitch p99, p99.9, max).
